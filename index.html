Поиск и создание файлов и каталогов

▶
Поиск файлов и каталогов
find / -name "file1"                          # найти файлы и каталоги с именем file1 от корня
find / -user user1                            # найти файлы, принадлежащие пользователю user1
find /home/user1 -name "*.bin"                # файлы с расширением .bin в каталоге /home/user1
find /usr/bin -type f -mtime -10              # файлы, изменённые за последние 10 дней
find /usr/bin -type f -atime +100             # файлы, к которым не обращались > 100 дней
locate "*.ps"                                 # быстрый поиск по базе (перед этим: updatedb)
which halt                                    # полный путь к исполняемому файлу
whereis halt                                  # расположение бинарника, исходников и man-страниц
Создание, копирование, перемещение, удаление
mkdir dir1                                    # создать каталог dir1
mkdir -p /tmp/dir1/dir2                       # создать дерево каталогов (включая родительские)
touch file1                                   # создать пустой файл
cp file1 file2                                # скопировать file1 в file2
cp -a /tmp/dir1 .                             # рекурсивно скопировать каталог с атрибутами
mv dir1 new_dir                               # переименовать / переместить
ln -s file1 lnk1                              # создать символическую ссылку
rm -f file1                                   # удалить файл (без подтверждения)
rm -rf dir1                                   # ОПАСНО: рекурсивно удалить каталог со всем содержимым
Команды rm -rf необратимы. Перед удалением каталогов убедитесь, что путь указан верно, особенно при работе от root.

Поиск аномально крупных файлов и удаление

▶
Найти крупные файлы
df -h                                         # использование дисковых разделов
du -sh /* | sort -rh | head -20               # топ-20 самых тяжёлых элементов в корне
du -ah --max-depth=1 | sort -rh | head -10    # топ-10 крупнейших файлов/каталогов в текущем каталоге
find / -type f -size +100M -exec ls -lh {} \; # файлы > 100 МБ с человекочитаемым размером
find /var/log -type f -name "*.log" -size +50M # крупные лог-файлы в /var/log
Удаление крупных / старых файлов
find /path -type f -size +100M -exec rm -f {} \;       # удалить все файлы > 100 МБ в /path
find /path -type f -name "*.log" -size +100M -exec rm -f {} \; # удалить крупные .log
find /var/log -type f -name "*.log.*" -mtime +7 -exec rm -f {} \; # удалить логи старше 7 дней
rm -rf /tmp/*                                 # осторожно: очистить /tmp
Перед удалением логов убедитесь, что сервис не держит файл открытым. Для активных логов лучше использовать truncate -s 0 file.log.

PHP — проверка версий и перезагрузка

▶
Проверка версий и окружения
php -v                                        # версия PHP в CLI
php --ini                                     # путь к php.ini
php -m                                        # список подключённых модулей
ls /etc/php-fpm.d/                            # конфигурации пулов php-fpm
systemctl status php-fpm                      # статус основного сервиса
Перезагрузка PHP-FPM (включая именованные версии)
systemctl restart php-fpm                     # стандартный php-fpm
systemctl restart php7.4-fpm                  # если установлена версионная сборка
systemctl restart php8.1-fpm                  # пример для PHP 8.1
systemctl reload php-fpm                      # мягкая перезагрузка без разрыва соединений
Если используется fm (FastCGI Manager), имя юнита может отличаться: проверьте systemctl list-units | grep -i fm. Для нескольких версий PHP удобно использовать systemctl restart php*-fpm после проверки списка юнитов.

Nginx, Apache (и другие веб-серверы) — проверка и перезагрузка

▶
Проверка статуса
systemctl status nginx                        # статус Nginx
systemctl status httpd                        # статус Apache (httpd)
ss -tulnp | grep -E ':80|:443'                # кто слушает 80 и 443 порты
nginx -t                                      # проверка конфигурации Nginx
httpd -t                                      # проверка конфигурации Apache
Перезагрузка
systemctl restart nginx                       # полная перезагрузка Nginx
systemctl reload nginx                        # мягкая перезагрузка (без разрыва соединений)
systemctl restart httpd                       # полная перезагрузка Apache
systemctl reload httpd                        # мягкая перезагрузка Apache
systemctl restart varnish                     # если стоит Varnish
systemctl restart haproxy                     # если стоит HAProxy
Перед restart полезно проверить синтаксис: nginx -t или httpd -t. Для боевых серверов предпочтительнее reload — он не разрывает активные соединения.

Перезагрузка баз данных

▶
MySQL / MariaDB
systemctl status mysqld                       # статус MySQL
systemctl restart mysqld                      # перезагрузка MySQL
systemctl status mariadb                      # статус MariaDB
systemctl restart mariadb                     # перезагрузка MariaDB
PostgreSQL
systemctl status postgresql                   # статус PostgreSQL
systemctl restart postgresql                  # перезагрузка PostgreSQL
Другие СУБД
systemctl restart mongod                      # MongoDB
systemctl restart redis                       # Redis
Перезагрузка БД разрывает активные запросы. Выполняйте в окно обслуживания и предварительно делайте резервную копию.

Мониторинг нагрузки и зависших соединений

▶
Общая нагрузка (CPU, память, диск)
top                                           #实时: CPU, память, процессы
htop                                          # более удобный интерактивный монитор (yum install htop)
uptime                                        # load average за 1/5/15 минут
free -h                                       # использование оперативной памяти и swap
vmstat 1 5                                    # виртуальная память, CPU, I/O (5 снимков каждую секунду)
iostat -x 1 5                                 # детальная статистика дискового I/O
df -h                                         # заполненность разделов
Сетевые соединения и «зависшие» сокеты
ss -tulnp                                     # все слушающие TCP/UDP порты с процессами
ss -tan state established                     # только установленные соединения
ss -tan state time-wait | wc -l               # количество сокетов в TIME_WAIT
ss -tan state close-wait                      # сокеты в CLOSE_WAIT (частый признак утечки)
ss -s                                         # сводка по всем типам сокетов
netstat -anp | grep :80 | wc -l               # количество соединений на порту 80 (если установлен netstat)
iftop -i eth0                                 # трафик в реальном времени по соединениям
tcpdump -i eth0 -nn port 80                   # анализ пакетов на порту 80
Большое количество сокетов в CLOSE_WAIT часто указывает на то, что приложение не закрывает соединения. TIME_WAIT — нормальное состояние, но при тысячах таких сокетов стоит проверить net.ipv4.tcp_tw_reuse.

Настройки iptables

▶
Установка и базовые операции
yum install iptables-services -y              # установка (RHEL/CentOS)
systemctl start iptables                      # запуск
systemctl enable iptables                     # автозапуск
iptables -L -v -n                             # просмотр правил
iptables -F                                   # ОПАСНО: очистить все правила
service iptables save                         # сохранить правила (CentOS 6/7)
iptables-save > /etc/sysconfig/iptables       # альтернативное сохранение
iptables-restore < /etc/sysconfig/iptables    # восстановить правила
Примеры правил
# Политики по умолчанию
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

# Разрешить loopback
iptables -A INPUT -i lo -j ACCEPT

# Разрешить уже установленные соединения
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# Открыть порты
iptables -A INPUT -p tcp --dport 22 -j ACCEPT    # SSH
iptables -A INPUT -p tcp --dport 80 -j ACCEPT    # HTTP
iptables -A INPUT -p tcp --dport 443 -j ACCEPT   # HTTPS

# Заблокировать IP
iptables -A INPUT -s 192.168.1.101 -j DROP

# Разрешить только определённый IP на порт
iptables -A INPUT -p tcp --dport 3306 -s 10.0.0.5 -j ACCEPT
На CentOS 7+ по умолчанию используется firewalld. Если вы ставите iptables-services, отключите firewalld: systemctl disable --now firewalld.

Настройки fail2ban

▶
Установка и запуск
yum install epel-release -y                   # подключить EPEL (CentOS 7)
yum install fail2ban -y                       # установка
systemctl enable --now fail2ban               # запуск + автозапуск
Конфигурация
cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local   # создать локальный конфиг (не трогать jail.conf)
vi /etc/fail2ban/jail.local                            # редактировать jail.local
Пример jail.local для SSH
[DEFAULT]
bantime  = 86400          # бан на 24 часа (в секундах)
findtime = 600            # окно наблюдения — 10 минут
maxretry = 5              # макс. попыток до бана
banaction = iptables-multiport

[sshd]
enabled  = true
port     = ssh
filter   = sshd
logpath  = /var/log/secure       # для CentOS/RHEL
maxretry = 3
bantime  = 86400
Управление и проверка
systemctl restart fail2ban                    # перезапуск после правки конфига
fail2ban-client ping                          # проверка: должен ответить "pong"
fail2ban-client status                        # список активных jail
fail2ban-client status sshd                   # статистика по SSH: забаненные IP
iptables -L INPUT -v -n | grep f2b            # проверить, что правила fail2ban применились
На CentOS 7 используйте banaction = firewallcmd-ipset, если firewalld активен. В примере выше — iptables-multiport для классического iptables.
